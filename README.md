# Telegram Dating Bot (ML RecSys + NLP)

Telegram-бот для знакомств.

---

## Что уже сделано

### Шаг 1 &mdash; минимальный бот
Бот отвечает на `/start`. Ни БД, ни ML — только проверка,
что токен и aiogram работают.

### Шаг 2 &mdash; хранение анкеты в БД
Простая анкета: **имя** и **возраст**. Бот последовательно спрашивает данные
и сохраняет их в базу.

- БД: **SQLite** (файл `storage/bot.db`), доступ асинхронный через SQLAlchemy
- При повторном `/start` бот узнает пользователя и не создает анкету заново

### Шаг 2.5 &mdash; логирование
Логирование через стандартный модуль `logging`, вывод только в консоль.


### Шаг 3 &mdash; расширение анкеты
Теперь бот спрашивает имя, возраст, пол, кого ищем, био, фото и сохраняет все в БД.

### Шаг 4 &mdash; BERT-эмбеддинг анкеты
После заполнения анкеты бот строит эмбеддинг из текста био
(`sentence-transformers`, модель `paraphrase-multilingual-MiniLM-L12-v2`).

- Модель грузится один раз при старте бота (`bot/services/embedding.py`) и переиспользуется для всех пользователей
- Эмбеддинг хранится в `users.embedding` как json-строка
- Пока эмбеддинг только считается и сохраняется, сам подбор анкет по нему появится позже

### Шаг 5 &mdash; просмотр анкет (`/find`)
Команда `/find` показывает подборку подходящих по полу/предпочтениям анкет. Отбор реализован пока без ML. Также добавил удаление анкеты через `/delete`

### Шаг 6 &mdash; ранжирование по эмбеддингам (retrieval)
`/find` теперь подбирает анкеты **по семантической близости био**, а не случайно. Я решил временно отказаться от PostgreSQL. Потом если что можно будет переехать, сейчас это излишне.

### Шаг 7 &mdash; лайки, дизлайки, мэтчи, уведомления
Теперь лайк/пропуск/дизлайк под каждой анкетой в `/find`. Взаимный лайк создаёт `Match`, оба пользователя получают уведомление с контактами друг друга. Команды для удобного интерфейса (/likes, /create/, /me, /matches). Также уведомление приходит при лайке.

### Шаг 8 &mdash; кластеризация анкет по интересам
Отдельный скрипт `cluster_users.py` берёт все анкеты с эмбеддингом и через `MiniBatchKMeans` (`bot/services/clustering.py`) распределяет их по кластерам интересов, записывая `cluster_id` в БД.

### Шаг 9 &mdash; гибридный ранкинг
`/find` теперь сортирует кандидатов не только по семантической близости био, а по **гибридному скору**
score = 0.6 * семантическая близость + 0.15 * бонус за общий кластер + 0.25 * implicit-фидбэк лайк/дизлайк + 0.2 * за близость по возрасту

### Шаг 10 &mdash; контейнеризация (Docker)
Проект упакован в Docker: `Dockerfile` + `docker-compose.yml`.

## Структура проекта

```
telegram_rag_bot/
├── bot/
│   ├── main.py            # точка входа
│   ├── config.py          # настройки, переменные
│   ├── logger.py          # настройки логирования
│   ├── handlers/
│   │   └── onboarding.py  # регистрация пользователя: /start и /create
│   │   └── browsing.py    # просмотр анкет: /find и /likes
│   │   └── profile.py     # управление анкетой: /me и /delete
│   │   └── matches.py     # список метчей: /matches
│   │   └── fallback.py    # ответ на непонятное сообщение
│   └── services/
│       └── embedding.py   # построение BERT-эмбеддинга анкеты
│       └── ranking.py     # ранжирование кандидатов по близости эмбеддингов
│       └── clustering.py  # кластеризация анкет по интересам (MiniBatchKMeans)
├── storage/
│   ├── models.py          # User, Interaction, Match (SQLAlchemy)
│   ├── database.py        # асинхронный движок + фабрика сессий
│   ├── repository.py      # функции доступа к данным
│   └── bot.db             # файл SQLite
├── cluster_users.py       # пересчитывает кластеры интересов
├── Dockerfile
├── docker-compose.yml
├── .dockerignore
├── .env.exa    mple
├── requirements.txt
└── README.md
```
